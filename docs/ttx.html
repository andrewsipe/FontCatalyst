Subcommand

TTX

Dump a font, or every font in a directory, to XML. The ttx program takes one file. This command takes a tree.

fontcatalyst ttx fonts/ -r
fontcatalyst ttx Family.ttf
fontcatalyst ttx fonts/ -r -ct

What it writes

Each TTF, OTF, WOFF, or WOFF2 becomes a .ttx file beside it. The binary stays where it was. ttx is run with --no-recalc-timestamp, so the modified time written into the XML is the one already stored in the font. Two dumps of the same font match.

Running it again

-r does not walk _archive, _quarantine, _ttx, or _ttx_top. A font that is still in the source folder, with a matching .ttx already written, is left alone. The font is not renamed, and a #1 copy is not added. A different font that happens to share the stem still gets #1.

When those folders are the only fonts left, the line is: Skipping _archive, _quarantine and _ttx, _ttx_top directories: No TTF, OTF, WOFF, or WOFF2 files found.

Repair is separate. --repair on the default command is still the only path that rebuilds a font through TTX, and only when a table will not decompile.

Folders

  • Default — Family.ttx next to Family.ttf
  • -o DIR — every .ttx in DIR. Sources stay
  • -c — _ttx/ in each source folder, originals in _archive/
  • -ct — one _ttx_top/, originals in _archive/ beside it

_quarantine/ is created only when ttx fails. -r walks subdirectories.
